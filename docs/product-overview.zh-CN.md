# ORION：企业本体工程与证据问答工作台

ORION 在官方 DeepSeek Harness 上提供一套企业本体工作台：从业务目标和资料出发，组织本体建设、校验、批准与发布，再围绕正式发布版本开展可追溯的问答和分析。

适合需要把文档、业务概念和数据库来源联系起来，并对结果来源、版本和审批过程负责的团队。它可以帮助本体工程人员建设资产，也为业务使用者提供统一的查看和问答入口。

## 先体验什么，怎样才算跑通

安装后可先体验工作台、工程模板、本体中心及玻璃/壁纸设置。首次没有自己的本体和业务数据；要完成真实建设、发布和证据问答，还需准备模型账号、授权资料或只读数据源，以及 Protégé、Semantica 等相应外部软件。

资料、数据库和联合工程所需服务有所不同，完整包没有包含所有外部环境。软件名称、用途和官网见 [使用前准备清单](dependencies-and-acceptance.zh-CN.md)，按自己的使用范围准备即可。

**闭环要看真实结果：** 授权来源 → 工程审阅与人工批准 → 实际构建和校验 → 正式版本发布并回读 → 真实问答及可追溯证据。安装成功或界面可见不等于业务跑通；缺少的条件和未验证的环节应如实说明。

## 可以做什么

| 功能 | 使用者的操作与结果 |
| --- | --- |
| 发起本体工程 | 在新会话填写工程发起模板，选择资料、数据库或联合建设，描述业务目标与希望回答的问题 |
| 管理资料和来源 | 使用自己的资料工作区，通过文件引用、资料任务和受控数据源建立可追溯输入 |
| 推进工程 | 在本体中心查看阶段、决定、校验和批准，按 S0–S7 规则推进工程 |
| 管理本体与模板 | 集中查看本体资产、正式版本和行业模板；模板可作为建设参考，实际业务仍需校验 |
| 查看图谱 | 浏览指定工程、模板或发布版本的本体结构和实例，进行搜索、筛选与定位 |
| 证据问答与分析 | 对已批准发布的本体及授权来源提问，查看版本绑定和证据；数据库分析按实际连接与权限执行 |
| 个性化界面 | 使用液态玻璃、流体背景、图片或视频壁纸，独立调整 Aqua 外观 |

例如，团队想梳理“设备、巡检和工单”的关系，可以先选定获授权的手册、制度和业务表，发起本体工程，确认概念、来源与规则，完成校验和人工批准后发布。随后提出业务问题，并核对答案所引用的正式版本和证据。这个例子说明使用路径；交付包不自带客户业务数据，也不代表该场景已完成验收。

## 两个插件与后台如何配合

```text
使用者：选择官方桌面或本机浏览器
                  ↓
DeepSeek Harness：会话、模型、通用工具与插件宿主
    ├─ ORION 工作台：工程、本体中心、资料、图谱、证据界面
    │        ↓
    │   ORION Python 服务：工程规则、业务执行、发布与证据
    │        ↓
    │   使用者自己的资料、数据库及按需部署的业务工具
    └─ Aqua：玻璃、流体背景与图片/视频壁纸
```

| 交付组件 | 版本 | 负责什么 |
| --- | --- | --- |
| `dsh-orion-workbench` | `1.0.0-rc.8` | 本体工作台与工程/问答技能，连接并管理配套本地服务 |
| `dsh-client-ui-aqua` | `1.3.1-orion-alpha.4` | 独立外观插件，保留上游许可和来源 |
| `dsh-orion-runtime` | `1.0.0-rc.8` | 完整 Python 服务源码、锁定依赖、契约、模板与配套测试；不是第三个界面插件 |
| DeepSeek Harness | `0.2.0-rc.2` | 官方宿主；Apple 芯片 Mac 官方 DMG 随完整交付包提供 |

工程、资料、本体管理、行业模板、图谱、问答和分析当前统一随工作台版本维护。Aqua 可单独开关；关闭两个插件后可恢复当前宿主的官方原生界面。插件开关不会自动删除业务资料或会话。

## 选择桌面还是 Web

| 选择 | 适合怎样使用 | 当前范围 |
| --- | --- | --- |
| 官方桌面端 | 平时从 Mac“应用程序”启动，使用原生窗口和设置 | Apple 芯片 Mac；推荐第一次安装采用 |
| 本机 Web 端 | 在自己电脑启动官方 Web 宿主，再用浏览器访问 | 独立 Node、Home、业务 Profile 和端口；无需先安装桌面 App |

两种入口使用同一套插件和 Python 服务代码。若同时部署，应为两个运行实例分别准备业务目录和端口，避免同时写入同一 Profile。

当前后台运行在使用者本机。完整的远程多人服务器模式还需要远程工作流 API、认证权限、资料传输和任务隔离等实现与验收；RC8 不能仅修改一个服务 URL 就变成完整服务器部署。

## 下载后怎样开始

1. 取得 `orion-rc8-delivery-kit-r2.zip` 和配套 SHA-256 校验文件，解压为 `ORION-RC8` 文件夹。
2. 阅读 `README-先读.txt`，选择 [桌面安装](install.zh-CN.md) 或 [Web 安装](web-install.zh-CN.md)。
3. 按教程校验文件，在自己的电脑准备 Python 环境、独立业务目录和模型账号。
4. 安装插件、配置完整服务路径，再检查模板、资料引用、后台身份和实际业务结果。

仓库已公开，可直接打开 RC8 Release 下载，无需 GitHub 账号或邀请；也可以直接接收完整 ZIP。公开可读不授予本仓库写入权限。如果由 AI 操作本机，可使用 [AI 部署任务说明](ai-deployment.zh-CN.md)。

## 交付范围

完整包包含官方 Apple 芯片 Mac 安装包、两个成品插件、Python runtime 源码、安装配置辅助脚本和教程。官方 App 保留原签名及原始文件，ORION 不改它的程序内容。

Python/Node 运行环境及依赖在首次安装时按教程联网获取。使用者自行提供模型账号、获授权的业务资料与数据源；外部能力按准备清单和所选业务范围部署，其中部分是正式阶段的必需条件；它们没有全部包含在下载包内。没有正式本体发布时，证据问答尚无可用发布版本，这是初始空环境的正常状态。

RC8 是预发布候选，延续 RC7 的隐私清理并修正 Python 包版本一致性。桌面原生开关和 Web 首页入口已有 RC6 基线；RC8 新增检查以发布页为准。收件机器上的模型调用、实际资料接入和客户业务链需要安装者验收。界面出现或健康接口可访问不等同于业务已通过。

ORION 自有代码仍标记 `UNLICENSED`，本次公开下载未改动许可；Aqua 等第三方组件保留各自许可与来源。下载、部署自己的副本与取得公开再分发授权是不同事项。
