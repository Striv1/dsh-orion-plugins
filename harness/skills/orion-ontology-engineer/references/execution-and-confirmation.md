# 执行、确认与异常处理协议

仅在初始化任务面板、处理人工决定、认证/执行异常或核对正式完成回执时读取。阶段输入仍以当前机器合同为准。

## 3081 启动与认证边界

- 工程构建不是运维授权。3081 已运行时，不启动第二个实例，不自行停止、重启或切换端口、Harness/Node 版本与运行目录。
- 插件通过官方 Profile 与 runtime-manager 生命周期管理运行；工程建设不是运维授权。仅在用户明确要求启停维护时，按 docs/runtime-install.md 和已配置的 Profile 入口操作，不启动旧工作台或第二个 Harness 实例。
- 浏览器登录与 Agent 的 HTTP 调用认证是不同上下文。HTTP 401/403 不等于 3081 未启动，也不等于业务阶段质量失败；不得通过重启服务、关闭认证、读取凭据或索要 Token/带密钥 URL 解决。
- S0 批处理由已认证的前端或已挂载的受控平台工具触发。拿到接口路径不代表当前会话拥有调用身份；`x-orion-document-confirmation` 是操作确认，不是身份认证。
- 当前会话没有受控调用入口时，报告“平台执行入口未接通”，保留工程与已完成成果，等待平台接入处理。不得编造未挂载的工具，也不得生成“已登录即可继续／提供认证 URL”等让业务用户选择内部认证方式的决策卡。只有实际页面显示用户登录已失效，才请用户在原页面正常登录，不要求传递凭据。

## Harness 原生任务与关键确认

- 构建开始展示完整 S0～S7 任务列表。平台从可信工作流回执同步到 Harness 原生任务面板；尚未绑定工程时可调用 `todo_write` 建立初始计划，绑定后只回读正式状态来更新面板，不用 `todo_write` 替换正式阶段。使用真实阶段合同名称，不把资料工程的数据库子任务不适用写成整个 S1 未验证。
- `todo_write` 接收完整 `todos` 数组，每项只有 `content` 和 `status`，状态为 `pending`、`in_progress`、`completed`。它是整表替换，不是增量补丁。绑定工程后的具体子任务在阶段说明中列出，不替换正式任务面板；只有真实通过才能完成勾选。失败项写明待修复，待决策项写明等待确认，不能提前勾选通过。原生面板每轮会重置，继续或恢复时按当前正式状态重新同步。
- 默认只在关键节点调用 `ask_user_question`：S0～S3 无法安全判断的业务歧义、v2 S4 整体设计、S7 具体版本发布。正常技术检查及已授权阶段继续执行，不每阶段重复审批。
- 先展示中文业务摘要、证据/报告入口、推荐方案及影响，再调用原生确认卡。问题使用 `questions:[{id,header,question,options:[{label,description}],multi_select:false}]`；`id` 绑定当前工程、revision 与决策 ID，标签与正式选项逐一对应。S4 是确认整套本体/映射/规则/CQ 或退回修改；S7 是批准该版本发布或暂缓。只使用当前真实选项，不编造不存在的阶段决策。
- 等待原生 `answers` 的真实选择。`selected:[]`、跳过、关闭、`ASK_CANCELLED`、`ASK_ABORTED` 或 `NO_PROVIDER` 都不是批准；保留当前未完成状态。自定义回答若含条件或歧义，先明确其含义，不能只抽取一个“同意”。原生能力不可用时明确该交互入口未接通，不伪造用户回答。
- 取得选择后重新核对当前工程、阶段和待审依据，仍匹配才调用已有 `resolve_mapping_option`、`resolve_mapping_confirmation`、`resolve_competency_question_review` 或 `publish_ontology_package` 等当前推荐的正式工具。记录真实用户决定和操作者，回读状态、决策/发布审计及产物；确认卡返回不等于阶段已通过。已对同一具体依据明确批准的事项不重复提问。
- 问答卡使用 Harness 原生输入区交互，不用浏览器 `alert/confirm`，不创建另一套审批状态，也不把内部续跑指令塞进输入框。

## 阶段完成的统一判定

一次阶段推进只有同时满足以下条件才算完成：

1. 工作流状态和 revision 已回读；
2. 当前阶段正式机器资产已持久化；
3. 阶段报告与资产 manifest 已生成；
4. 必要的外部工具执行回执真实、属于当前工程和当前 revision；
5. 工作流事件/审计链已追加；
6. 再次回读显示阶段真实前进。

缺任一项都只能报告“已执行到哪一步”，不能说“阶段已通过”。

## HTML 阶段报告

- 统一由 Workflow 服务的报告模块（`services/ontology_engineering/reporting.py`）确定性生成；模型不直接拼装简陋 HTML。
- 每阶段保留一份主报告，同时保留 JSON/YAML/SQL/OWL/TTL、图表脚本和本地依赖。HTML 不替代机器资产。
- 报告包含执行摘要、范围、量化指标、证据、质量边界、风险/未验证项、下一阶段交接和来源清单。
- 图表使用本地 ECharts 独立 JS；禁止 CDN。无正式证据的结论标为“尚未验证”或“待确认”。

## 强制停止条件

- 前一阶段未通过，或工具结果与持久化状态不一致；
- 数据源不明确、来源授权缺失或只读边界无法保证；已明确授权的生产来源只读查询不因“生产”标签再次索取相同授权；
- 当前来源模式及能力合同要求的 Protégé、HermiT、SHACL、Ontop/Fuseki、Semantica 或 CQ 检查缺少真实回执；不因未声明或不适用的引擎缺回执而臆造新任务；
- 业务规则缺少事实来源、法律依据、运行算子或正反边界测试；
- MCP 工具未挂载、session 失效且一次受控恢复后仍不可用；
- v2 S4 整体设计尚未获得本次明确确认，或已到 S7 但用户尚未明确批准发布。
- S7 发布包已经通过而 runtime 部署失败时，保持包与批准记录，状态为 `PACKAGE_READY_RUNTIME_BLOCKED`；只恢复运行时部署/验证，不回退本体质量阶段。

停止时说明：当前阶段、已完成证据、主因、未完成项和一个可执行的恢复动作。

## 禁止事项

- 不绕过 `orion_workflow` 直接修改状态、Mapping、报告、审批或审计日志。
- 不执行数据库写操作，不伪造任何工具、门禁或发布回执。
- 未获明确授权，不自动替用户批准 v2 S4 整体设计或 S7 发布。范围、执行、设计确认和发布是不同授权；一般“继续”不代替具体设计或发布批准。用户明确委托当前工程的确认或批准发布时，不重复索要相同授权：先审阅当前具体候选、版本与真实质量回执，再调用相应决策工具；记录授权人、实际代理操作者和采用依据，不冒称用户亲自点击。代办不免除任何门禁、不扩展至其他工程，不得把平台续跑通知本身当成审批授权。
- 不用超过 3 张阻塞型建模决策卡，不把安全默认值包装成人工决定。
- 不扫描源码、日志、临时目录来猜当前工程；不读取 token/credential 来旁路 MCP。
- 不向用户输出“加载 Skill”、系统上下文、内部分析或长篇工具过程。
- 不把工具名、字段名、SPARQL binding、`role` 命名、Schema 或门禁内部修复伪装成“需要用户提供的业务信息”。

面向用户始终使用简体中文；标识符、字段名、路径、工具名和必要本体术语保留英文。每次只报告当前阶段、已完成事项、阻塞问题和下一步。
